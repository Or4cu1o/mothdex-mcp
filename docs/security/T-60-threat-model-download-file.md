# T-60: Threat model, `mothdex-mcp` `download_file` and v0.2.0 distribution

Status: v1 · Author: Sentinela · Date: 2026-11-21 · Risk: **High** · Consumers: Alicerce (tools.md §3, plugin.md §5),
Bigorna (implementation), Ensaio (tests), Guindaste (npm, `.mcpb`, registry release steps)
Gate: no `download_file` code merges before the contract changes in §7 are accepted, or explicitly rejected by Regente.

## 0. Scope, method, limits

**In scope:** E-M3' (`mcp v0.2.0`). The opt-in `download_file` tool covers configuration and registration, destination
resolution (configured directory, MCP roots), link selection, the HTTP fetch, the `.part` file, verification, the
final name, the no-overwrite finalize, cleanup, concurrency, progress and cancellation, and tool output. Distribution
covers npm with provenance, `.mcpb`, and `server.json` in the official MCP registry.

**Out of scope:** the read tools of v0.1 (reviewed in T-30..T-34), non-proxy hosts (E-v0.2-hosts, D16), the content of
ROMs (never executed or extracted), the client's own permission UI (we rely on it but do not control it), and the
GitHub release workflow already audited in PR-12-sec and PR-12-sec-2 (only its new npm, mcpb and registry steps are
here).

**Inputs:** mothdex-cli `docs/security/T-16-threat-model-downloader.md`, whose TH and case numbers are reused below as
`T16/TH-nn` and `T16/#nn`. Also mothdex-mcp `docs/contracts/mcp/tools.md` §1–§3 and `plugin.md` §1, §5, research T1c
and T1d, the source on main bf994da (`src/server/config.ts`, `links.ts`, `src/api/transport.ts`), and ROADMAP E-M3'
and D16 (proxy links only until E-v0.2-hosts).

**Method:** STRIDE per data flow, a reuse check against T-16, local non-destructive probes of Node 26.12.1 behavior
(Linux), and a reading of the official docs listed in §1.

**Tools:** manual review, `grep`, Node probes in a scratch directory. No scanner applies, because there is no
implementation yet.

**Not verified:**

- Windows behavior of `fs.realpath.native` on junctions.
- Behavior on FAT/exFAT for `fs.link`.
- Claude Desktop's handling of roots and of `.mcpb` signatures.
- The runtime value of an unset optional plugin `userConfig`.
- npm granular-token expiry limits.

This document does not claim the design is free of vulnerabilities.

## 3. Actors and trust boundaries

**Actors:**

- **(A)** A malicious or compromised upstream (Mothdex API/DB, a scraped source, the proxy). This is T-16 actor A.
- **(P)** A prompt-injection author: anyone who can put text into catalog data, a web page or a file the model reads in
  the same session.
- **(M)** The model itself, which makes mistakes (wrong entry, repeated calls).
- **(L)** A local or shared-folder attacker with write access to the download directory. This is T-16 actor C.
- **(S)** A supply-chain attacker: a hijacked dependency, CI or account, or a typosquat package.
- **(U)** The user, by mistake (bad directory, enabling the tool globally).

User configuration (env and plugin `userConfig`) is trusted but validated, and fails closed.

```
 [Mothdex API] --JSON Link/Entry--> |B1| --> api client --> cache(LRU) --> download_file
 [LLM via MCP client] --tools/call {slug, link_index}--> |B7| -------------------^   |
 [proxy] --HTTP body--> |B2| -------------------------------------------------------^  |
 [client] --roots/list (advisory)--> |B8| --> destination resolution                  |
 local FS (download dir) <== |B3| .part, link/finalize, cleanup <---------------------+
 download_file result --> |B9| --> LLM context (remote provider)
 [CI: GitHub Actions OIDC] --> |B10| npm / GitHub Release (.mcpb) / MCP registry --> users' clients
```

| Boundary   | What crosses it                             | Trust                                                                                          |
| ---------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| B1, B2, B3 | API data, the proxy body, filesystem writes | As in T-16. Every Link field is untrusted, and checks run at use, also for cached data.        |
| **B7**     | Tool arguments from the model               | Untrusted. Validated by schema; they carry no path, name, URL, size or overwrite choice.       |
| **B8**     | Roots from the client                       | Advisory (F2). At most a candidate directory, validated as strictly as `MOTHDEX_DOWNLOAD_DIR`. |
| **B9**     | Tool output back to the model               | Minimal, sanitized, no secrets, no instructions.                                               |
| **B10**    | Release pipeline to the registries          | Supply chain. Short-lived OIDC credentials only.                                               |

## 6. Test cases (implementation must cover all before merge)

Fakes: a TLS test proxy (`https.createServer` with a test CA passed to the client only in tests), a temp dir per test,
an injected clock and sleeper (no real sleeps), and an FS seam for race hooks. **[L]** marks Linux-only cases and
**[W]** marks Windows CI cases. Name cases form one table test.

**Registration and configuration**

1. Enable flag values `""`, `0`, `true`, `yes`, ` 1`, `1 ` → tool not in `tools/list`; `1` with a valid dir → listed. Read tools work in every case.
2. `MOTHDEX_DOWNLOAD_DIR` unset, `""`, `"   "`, `${user_config.download_dir}`, `relative/dir`, a missing path, a regular file → not registered, warning names the variable, no directory created anywhere.
3. The dir is `/`, `$HOME`, `~/.ssh`, `~/.claude`, `CLAUDE_PLUGIN_ROOT`, `.../roms/ports`, `.../ports_scripts`, `...\roms\windows`, and a symlink whose realpath is one of these → refused. **[L]** a `0777` dir without the sticky bit, and a dir under such an ancestor → refused.
4. `NODE_TLS_REJECT_UNAUTHORIZED=0` → not registered.
5. `MOTHDEX_ALLOWED_HOSTS=proxy.mothdex.net,archive.org` → read tools flag archive.org as trusted, but `download_file` on an archive.org link → `untrusted_url`, zero connections (fake dialer count).
6. (Only if OD-1 keeps roots) no second opt-in → roots ignored; two roots → `no_destination`; a non-`file://` root → ignored; a root changed between calls → re-read and re-validated.

**Input**
7. Extra keys (`path`, `filename`, `url`, `overwrite`, `dir`) → `invalid_request`, nothing fetched. `link_index` 0, −1, 1.5, a string, or > link count → `invalid_request`/`not_found`. Unsafe slug → `invalid_request`.

**Names (port of T16/#1–#12 using the shared fixture)**
8. Every T-16 Sanitize vector from mothdex-cli gives byte-identical output in TS (fixture divergence fails CI).
9. Deny-list: `x.sh`, `x.SH`, `x.zip.sh`, `x.desktop`, `x.exe`, `x.bat`, `x.lnk`, `x.ps1`, `x.AppImage` → `unsafe_name`, no file. There is no input or env that allows them. `x.bin`, `x.iso`, `x.chd`, `x.zip` → allowed.
10. Property test (fast-check or a seeded generator): random strings satisfy the T-16 §5.9 invariants and idempotence.
11. Flat layout: `entry.platform` = `../../x` or `ps1/../..` → the file still lands directly in the dir; no directory is created.

**Filesystem**
12. Final name already exists → `status: "exists"`, the existing file is byte-identical, no `.part` left.
13. Race: a hook creates the final name after preflight and before finalize → existing file preserved, `exists`.
14. **[L]** a dangling symlink at the final name pointing to a victim path → victim not created or modified, result `exists`.
15. **[L]** a symlink at the staging name → `wx` fails, a new random name is tried once, then error. Nothing outside the dir is touched.
16. **[L]** the dir is replaced by a symlink to another dir between preflight and finalize → finalize refused, `.part` removed, nothing written outside.
17. **[W]** the dir is a junction to outside a configured path, or the configured path itself is a junction → the realpath check behaves as specified (records the Unverified F-item).
18. `fs.link` fails with `EPERM`/`ENOTSUP` (fake) → `copyFile` with `COPYFILE_EXCL`; an existing final name → `exists`.
19. Static plus behavioral: finalize never calls `rename` onto the final name (FS seam spy).
20. Final file mode is `0o644` & ~umask, never executable; `.part` mode `0o600`.
21. Case collision: two queued calls resolving to `Game.zip` and `game.zip` → the second is `exists`, never an overwrite.

**Network**
22. URL table from T16/#26 (http, port 8443, userinfo, IP literals, trailing dot, uppercase, suffix host, `xn--`) → same accept and reject set as `isTrustedHost`, plus non-proxy hosts rejected; zero dials for rejected ones.
23. The proxy answers 301/302/307 → `untrusted_redirect`, not retried, `.part` removed.
24. `Content-Encoding: gzip` (and `br`, `deflate`) → refused before the body is read (assert the body stream was not consumed); a gzip body whose decoded length equals `link.size` is also refused (F6).
25. `Content-Length` missing, or ≠ `link.size` → `size_mismatch`; a body of `size+1` bytes → abort at byte `size+1`.
26. `link.size` ≤ 0, `Number.MAX_SAFE_INTEGER`, > the per-file cap → refused in preflight, no connection.
27. Self-signed TLS → fails; no option disables verification.
28. 404 with body `not found` → failure, nothing finalized.
29. A cached `entry` with a malicious `filename`/`url` → the same rejections as fresh data.

**Limits, concurrency, lifecycle**
30. Free space below `size + max(5 %, 256 MiB)` (fake statfs) → `disk_full` in preflight. `ENOSPC` mid-stream → `disk_full`, `.part` gone, ledger released.
31. Two concurrent calls → one runs, the other queued or `busy` per the contract, never two writers. The ledger counts the reserved bytes.
32. The 21st completed download, or a size crossing the total cap → `quota_exceeded`, nothing fetched.
33. `notifications/cancelled` during transfer → fetch aborted, `.part` removed, no result sent. A cancel arriving after completion → file kept, no crash.
34. Stdin closed mid-transfer → abort and cleanup before exit.
35. Startup cleanup: `.mothdex-<26>.part` with mtime 25 h is deleted; 23 h is kept; a symlink with that name is not followed (target intact); `notes.part` and a dir `x.part` are kept; nothing in subdirectories is touched.
36. Progress: with a `progressToken`, monotonic notifications, ≤ 1 per second (injected clock), none after the result; without a token, none.

**Output**
37. Result shape exactly `{status, path, bytes, sha256, crc}`. `sha256` matches the file. `path` is inside the realpath of the dir.
38. A filename or title holding `\x1b]52;...\x07`, `\u009b`, `\u009d`, `\u202e` or `\u2028` → the echoed text and the log line contain none of them.
39. Upstream error bodies and Node error messages (with paths) never appear in `structuredContent` or `text`.

**Distribution (Guindaste, release workflow; CI checks, no real publish in tests)**
40. `npm pack --dry-run --json` file list equals the allowlist exactly. The packed dist SHA-256 equals `dist/mothdex-mcp.mjs`. `package.json` has no `dependencies` and no lifecycle scripts.
41. The release workflow has no `NPM_TOKEN` or other long-lived npm secret. The npm step runs in the `release` environment with `id-token: write` only there. The npm and Node versions meet F10.
42. The `.mcpb` content list is exactly the manifest, dist and icon; its SHA-256 is in `checksums.txt`, in the attestation subjects and in `server.json` `fileSha256`. `mcpb validate` passes with the pinned CLI.
43. The manifest `user_config.download_dir` has no default; the enable flag defaults to off, and an unset value leaves the tool unregistered (end-to-end with the packed bundle where CI allows; otherwise not verified).
44. `server.json` name equals `package.json` `mcpName`, npm version equals the tag, the mcpb URL is under `github.com/Or4cu1o/mothdex-mcp/releases/download/<tag>/`, and `mcp-publisher` is pinned and Sigstore-verified before use.

## 8. Residual risk (after all CRs)

- **The user approves an injected call.** Server budgets bound the damage (disk, bandwidth), but a user who clicks
  "allow" on every prompt can still get unwanted files in the download dir. Med likelihood, Low–Med impact.
- **Directory race (F8):** a local attacker with write access to the parent of the download dir can swap components
  between the check and the open. Node has no `openat`. The flat layout and the finalize re-check narrow the window.
  Low.
- **FAT, exFAT and FUSE without hard links:** the `copyFile` EXCL fallback is no-replace but doubles I/O and briefly
  needs twice the space; the ledger must count it. Not verified on devices.
- **Windows junctions:** depend on `realpath.native` (Unverified, test 17).
- **Malicious ROM content** (as T16/TH-25): integrity is not authenticity.
- **Distribution:** registry preview data resets; `.mcpb` signature not enforced by clients (F11); the first npm
  publish may need a short-lived token (Unverified); a project-scope `.mcp.json` can run any command, which is the
  client's boundary.
